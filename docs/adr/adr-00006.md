# ADR-006: Android Client Runtime Dependencies (ruzstd, ndk, raw-window-handle)

**Status:** Accepted
**Date:** 2026-06-16
**Deciders:** Kevin (project lead)

---

## Context

Implementing the Android client (`waymux-client`) per ADR-004 (wgpu via JNI)
required a few dependencies not previously in the workspace, and revealed a
cross-compilation problem with an existing one.

1. **Zstd decode on the client.** The client only ever *decompresses* frames.
   The `zstd` crate (used by the bridge to *encode*) wraps the C `zstd-sys`
   library, which requires the Android NDK's C toolchain to cross-compile and
   adds a C build step to every client build.
2. **Native window + GPU surface.** Creating a wgpu surface on Android needs the
   `ANativeWindow` from the Java `Surface`, plus raw window/display handles.

---

## Decision

- **Client zstd decoding uses `ruzstd`** (pure-Rust, decode-only) instead of
  `zstd`. The bridge keeps `zstd` for encoding; the client keeps `zstd` only as
  a dev-dependency to build compressed test fixtures.
- **Add `ndk` (0.9)** for `NativeWindow`/`ANativeWindow_fromSurface`, and
  **`raw-window-handle` (0.6)** to construct the surface handles wgpu consumes.
  Both are Android-target-only dependencies
  (`[target.'cfg(target_os = "android")'.dependencies]`).

---

## Rationale

- `ruzstd` makes the client **pure Rust**: no C dependency, so it
  cross-compiles to `aarch64-linux-android`/`x86_64-linux-android` with only
  `rustup` targets + `cargo-ndk` — no NDK C compiler needed for the crate
  itself, and a smaller `.so`. It also lets the protocol/decode path be
  `cargo check`ed against the Android target on a host without the NDK.
- The client never compresses, so a decode-only decompressor is sufficient.
  Frames produced by the bridge's `zstd` encoder are standard zstd streams that
  `ruzstd` decodes; interoperability is covered by tests.
- `ndk` is the standard, maintained binding for Android native APIs and uses the
  same `jni-sys` types as the `jni` crate, so JNI pointers pass straight through
  to `NativeWindow::from_surface`. Its `rwh_06` feature matches wgpu 0.20's
  `raw-window-handle` 0.6.

---

## Consequences

- `ruzstd` is added to the workspace dependency set; `ndk` and `raw-window-handle`
  are added as Android-only dependencies.
- The client crate is `crate-type = ["lib", "cdylib"]`: a host-testable library
  plus the Android JNI shared object.
- If H.264 (ADR-002, deferred) is ever decoded on the client, it will use the
  Android `MediaCodec` path, not `ruzstd`; this ADR concerns lossless zstd only.
